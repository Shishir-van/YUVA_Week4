# Week 4 — ML Project Deployment & Capstone

A small end-to-end ML application that continues the Week 3 Breast Cancer Wisconsin experiment. It trains a Logistic Regression pipeline, serializes it with Joblib, and serves predictions through a FastAPI REST API.


## What is included

- `train_model.py` — loads the dataset, creates a stratified train/test split, trains the preprocessing + Logistic Regression pipeline, evaluates it, and writes the model artifact and metadata.
- `app.py` — FastAPI service with `/`, `/health`, `/model-info`, and `/predict` endpoints.
- `artifacts/model.joblib` — serialized model bundle, generated by `train_model.py`.
- `artifacts/metadata.json` — feature names, class mapping, library version, and test metrics.
- `tests/test_api.py` — basic API and input-validation tests.
- `docs/API_EXAMPLES.md` — example request and response.
- `Week4_Report.docx` and `Week4_Presentation.pptx` are provided separately alongside the project ZIP.

## 1. Set up on Windows

Open PowerShell in this project folder:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, you can call the environment's executable directly: `.venv\Scripts\python.exe -m pip install -r requirements.txt`.

## 2. Train and save the model

```powershell
python train_model.py
```

This creates or refreshes `artifacts/model.joblib` and `artifacts/metadata.json`. The StandardScaler stays inside the saved pipeline, so the API applies the same scaling at prediction time.

## 3. Run the API locally

```powershell
uvicorn app:app --reload
```

Open `http://127.0.0.1:8000/docs` for interactive Swagger documentation, or visit `http://127.0.0.1:8000/health` to confirm the service is running.

## 4. Test the API

In another terminal, from the project folder:

```powershell
pytest -q
```

## 5. Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | Basic service information |
| GET | `/health` | Health check |
| GET | `/model-info` | Model, feature list, class names, and test metrics |
| POST | `/predict` | Return predicted class and class probabilities |

The `POST /predict` request must provide every one of the 30 feature names exactly as returned by `/model-info`. The API validates missing or unknown fields and reorders valid fields to match training order.

See [`docs/API_EXAMPLES.md`](docs/API_EXAMPLES.md) for a payload example.

## Model and evaluation

- Dataset: scikit-learn Breast Cancer Wisconsin dataset (569 rows, 30 numeric features).
- Split: 80% training / 20% test, stratified, `random_state=42`.
- Pipeline: `StandardScaler` + `LogisticRegression(max_iter=3000)`.
- Evaluation metrics: accuracy, benign precision/recall/F1, malignant recall, and ROC-AUC.
- Because Joblib artifacts can be incompatible across scikit-learn versions, the tested core versions are pinned in `requirements.txt`. If you change versions, retrain the model with `python train_model.py` in the target environment.

## Deployment status and next step

This package is ready for local deployment and testing. It is **not automatically hosted on a public cloud**. For a cloud deployment, use a Python-compatible host, configure the build command as `pip install -r requirements.txt`, and the start command as `python train_model.py && uvicorn app:app --host 0.0.0.0 --port $PORT`. Protect real applications with HTTPS, authentication/rate limiting where appropriate, logging, resource limits, and a clear privacy/security policy.
